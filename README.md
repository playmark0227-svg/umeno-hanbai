# 梅乃寿司 販売管理

仕出し寿司店で 20年以上動いていた Access 2000 の販売管理システムを、
ブラウザで動くソフトに置き換えたもの。

**▶ <https://playmark0227-svg.github.io/umeno-hanbai/>**

売上伝票・入金伝票・請求書・売掛残高・得意先元帳・日報・月報・現金出納帳・
得意先／商品／仕入先の台帳・バックアップ／復元。

---

## このリポジトリに入っているもの

**画面のプログラムだけ**です。得意先の名前・住所・電話・売上金額といった
データは一切含みません。

データは使う人の手元にあります。

- 保存先を設定していないとき … 開いたブラウザの中（IndexedDB）だけ
- Firebase を設定したとき … その人の Firestore。ログインした人だけが見られる

どちらの場合も、このリポジトリにも GitHub にもデータは送られません。

## 作り

ビルド作業なし・依存ライブラリなしの素の HTML / CSS / JavaScript（ES modules）。
Firebase SDK だけ、保存先を設定したときに動的 import します。

```
index.html
css/app.css          意匠（藍・白木・朱／明朝見出し／青海波）
js/app.js            起動・画面切替・ログイン・保存先の設定
js/store.js          データ層（Firestore ⇄ IndexedDB）＋残高と請求の計算
js/ui.js             画面部品（表・ダイアログ・コード入力）
js/util.js           日付・金額・かな・消費税・締日
js/views/*.js        画面ごと
```

キー操作は Access に合わせてあります。
`Enter` 次の欄／`F4` 一覧から探す／`F1` 登録／`F12` 戻る。
右上の **小・中・大** で全体の文字が大きくなります。

### 設計で変えたところ

Access は得意先マスタに「繰越額・当月売上額・入金額」を**持ち回り**、
「日次更新」「年次繰越」で書き換えていました。走らせ忘れや二重実行で狂う構造で、
実際に移行元のデータでも 1社ぶん、伝票の無い 53,790円 が残っていました。

Web 版は持ち回りをやめ、**毎回伝票から積み直します**。

```
売掛残高 = 移行時残高 + Σ掛売(税込) − Σ入金
請求額   = 繰越 − 入金 − 入金値引 + 当月売上 + 消費税 − 値引
           （繰越 = 締め期間の前日時点の売掛残高）
```

日次更新・年次繰越という作業自体が無くなり、「確定」を押し忘れても金額がずれません。
